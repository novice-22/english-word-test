# 로그인 설정

이 앱은 **계정 1개**만 쓰는 것을 전제로 만들어졌다. 회원가입 페이지가 없고, 계정은 서버에서 직접 만든다.
비로그인 상태에서는 어떤 주소로 들어와도 소개 화면만 보이고, `/api/*` 는 전부 401로 막힌다
(예외: 로그인 자체인 `/api/auth/*` 와 가동 확인용 `/api/health`).

계정 정보는 `DATA_DIR/auth.json` 에만 저장된다. 이 파일은 `.gitignore` 에 등록돼 있어 저장소에 올라가지 않는다.

## 1. 계정 만들기 (필수)

**로컬에서 개발할 때:**

```bash
node server/setup-auth.mjs
```

**도커로 띄웠을 때:**

```bash
docker exec -it <컨테이너 이름> node server/setup-auth.mjs
```

물어보는 순서:

| 항목 | 설명 |
| --- | --- |
| 아이디 | 로그인에 쓸 아이디 |
| 비밀번호 | **12자 이상**. 입력해도 화면에 표시되지 않는다 |
| 비밀번호 확인 | 위와 동일하게 한 번 더 |
| 구글 클라이언트 ID / 시크릿 / 이메일 | 구글 로그인을 쓸 때만. 안 쓰면 그냥 Enter |
| 사이트 주소 | 배포 주소 (예: `https://your-domain.com`). 구글 OAuth 리디렉션 기준이 된다 |

저장하면 **서버 재시작 없이 즉시 적용**된다. 비밀번호를 바꾸려면 같은 명령을 다시 실행하면 된다
(빈 입력 = 기존 값 유지).

비밀번호는 scrypt 해시로만 저장되고 원문은 어디에도 남지 않는다.

## 2. 구글 로그인 (선택)

구글 계정으로 로그인하면 사이트에 비밀번호를 두지 않아도 되고, 구글의 2단계 인증이 그대로 적용된다.
비밀번호 로그인은 구글 장애 시 백업으로 남겨 두는 것을 권한다.

<details>
<summary><b>구글 클라우드 콘솔 설정 절차</b></summary>

1. https://console.cloud.google.com 접속
2. 상단 프로젝트 선택 → **새 프로젝트** → 이름 아무거나 → 만들기
   (기존 프로젝트가 있으면 재사용해도 된다. 무료이고 결제 정보도 필요 없다)
3. **API 및 서비스 → OAuth 동의 화면**
   - User Type: **외부** → 만들기
   - 앱 이름, 사용자 지원 이메일, 개발자 이메일 입력
   - 범위(Scopes)는 추가하지 않아도 된다 (기본 `openid`, `email` 만 사용)
   - **테스트 사용자**에 본인 구글 이메일을 추가한다 — 이걸 빼먹으면 로그인이 막힌다
   - 게시 상태는 **테스트**로 두면 된다. 본인만 쓴다면 앱 검증이 필요 없다
4. **사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
   - 애플리케이션 유형: **웹 애플리케이션**
   - **승인된 리디렉션 URI**에 아래를 추가한다. `your-domain.com` 을 **본인 도메인으로 바꿀 것**:

     ```
     https://your-domain.com/api/auth/google/callback
     ```

     `http://` 를 쓰거나 끝에 슬래시를 붙이면 구글이 거부한다.
     로컬에서 시험해 볼 때는 `http://localhost:3001/api/auth/google/callback` 을 추가로 등록한다.
   - 만들기 → **클라이언트 ID**와 **클라이언트 보안 비밀**을 복사해 둔다
5. `setup-auth.mjs` 를 다시 실행해 구글 항목을 채운다
   (아이디·비밀번호는 Enter로 넘기면 유지된다)

</details>

허용 이메일과 **정확히 일치하는 계정**만 로그인된다. 다른 구글 계정으로 시도하면
"허용되지 않은 구글 계정" 메시지가 뜨고 세션이 생기지 않는다.
첫 로그인에 성공하면 그 계정의 고유 ID(`sub`)가 고정 저장되어, 이후에는 이메일뿐 아니라 계정 자체가 일치해야 한다.

## 3. 동작 방식

- **세션**: HMAC 서명된 쿠키(30일). 15일 남으면 자동 연장되고, 최초 발급 후 180일이 지나면 재로그인이 필요하다.
  서버에 세션 저장소가 없어 재배포해도 로그인이 유지된다.
- **서명 키가 비밀번호 해시에서 파생된다** → 비밀번호를 바꾸면 **모든 기기의 기존 세션이 자동으로 무효**가 된다.
- **쿠키 속성**: `HttpOnly` + `SameSite=Lax`, `NODE_ENV=production` 이면 `Secure` 추가
- **CSRF**: `SameSite=Lax` + 상태 변경 요청의 Origin/Referer 검사 이중 방어
- **비밀번호 해시**: scrypt(N=32768). 로그인 처리는 비동기라 다른 요청을 막지 않고, 동시 2건으로 제한된다

### 로그인 시도 제한

| 대상 | 한도 |
| --- | --- |
| 비밀번호 (IP당) | 15분에 실패 5회 |
| 비밀번호 (전체 합산) | 15분에 실패 50회 — IP를 바꿔가며 시도하는 공격 차단 |
| 구글 콜백 (IP당) | 15분에 실패 10회 (버킷 분리) |

전체 상한에 걸리면 비밀번호 로그인이 15분간 잠긴다. 이때도 **구글 로그인은 그대로 된다**(버킷이 분리돼 있다).
둘 다 막혔다면 컨테이너를 재시작하면 즉시 초기화된다(카운터는 메모리에만 있다).

## 4. 세션 전부 무효화하기 (비상시)

가장 간단한 방법은 **비밀번호를 새로 설정**하는 것이다. 서명 키가 비밀번호 해시에서 파생되므로
비밀번호만 바꿔도 발급된 모든 세션이 즉시 무효가 된다.

구글 로그인만 쓰고 있다면 `auth.json` 의 `session_secret` 을 지우고 재시작한다
(새 값이 자동 생성되면서 기존 쿠키가 전부 무효가 된다).

```bash
docker exec <컨테이너> node -e "const f='/app/data/auth.json',fs=require('fs');const c=JSON.parse(fs.readFileSync(f));delete c.session_secret;fs.writeFileSync(f,JSON.stringify(c,null,2))"
docker restart <컨테이너>
```

## 5. 알려진 한계

- 프록시와 앱이 여러 컨테이너가 함께 쓰는 도커 네트워크에 있으면, 그 네트워크의 다른 컨테이너가
  침해됐을 때 프록시를 건너뛰고 앱에 직접 요청할 수 있다. 이 경우 `X-Forwarded-For` 를 위조해
  IP별 제한을 우회할 수 있으나, 위의 **전체 상한**이 무제한 대입을 막는다.
  더 조이려면 앱을 프록시와 단둘만 있는 전용 네트워크에 두면 된다.
- 로그인 실패 카운터는 메모리에만 있어 컨테이너 재시작 시 초기화된다.
